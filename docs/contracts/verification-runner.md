# Contract — Approved Isolated Test Runner

**Status:** P4 internal Linux bubblewrap adapter implemented at the dirty 0.1.4 checkpoint; independent native and multi-project qualification remains pending.

- A **trusted host controller** decides which signed/approved suite and command is callable for a gate. Pi Sitter requests a gate/run ID or approved rerun only; the supervisor model cannot choose the executable, script, flags, environment, test files or privileges.
- Initial runner executes Vitest and parses its **structured** output. Other frameworks can provide the same normalized report. Never embed Vitest assumptions in Pi Sitter's reasoning core.
- Start at completed milestones, at final verification, and after worker repairs for affected gates/regressions. Existing emergency triggers are not changed by this cadence.
- Execute through a no-shell interface with a bounded working directory, explicit exec/args allowlist, environment allowlist, timeout, process termination, memory/output/file caps and bounded logs.
- Permit only narrowly required read mounts, protecting implementation and protected acceptance tests from writes; provide disposable writable temp/cache/report paths. Restrict network and dangerous subprocess/host access; clean up even on error/cancel. A read-only mount of the whole host is **not** least-privilege confidentiality isolation.
- Verify source and suite identity before trusting the report. Sandbox unavailable, test-runner crash, missing report or policy violation are **BLOCKED**, not PASS.
- The P4 host adapter is an internal boundary, not a stable public wire API. The embedding host installs resolveApprovedVerifier(id, checkpoint). PI_SITTER_VERIFY_COMMAND is a JSON plan identifier; old command arrays and shell strings are rejected. The resolver returns a trusted ApprovedVerifier with an absolute executable, literal args, separate source snapshot and protected suite paths, explicit runtime library paths and bounded environment. It binds the plan to the checkpoint task ID, suite digest, source snapshot and gate subset. No project file, worker text, or supervisor output supplies execution authority. The injected verify dependency remains a trusted host adapter and must enforce equivalent isolation itself.
- A host may name up to four individual approved runtime binaries with `runtimeExecutables` when its suite needs an engine such as Godot. These binaries are checked as canonical executable files and mounted read-only. They do not grant the model a command choice. On shared-UID Linux hosts, `RLIMIT_NPROC` counts unrelated host threads; the adapter uses a finite 4096-thread limit alongside its CPU, memory, wall-time and concurrency bounds so an approved engine can start on a busy host.

- At a completed Worker boundary the host may return a loadCheckpoint signal for milestone, final, post_repair or manual. Milestone selection is deduplicated per task, milestone, source and suite in the live session; final covers every mandatory gate. Post-repair requires a changed source and retains failed gates plus selected regression gates. Without a host milestone signal, the existing completion-boundary final/recovery behavior continues. An ordinary tool edit does not schedule acceptance tests. The idle /sitter verify command and its budget remain.

- On Linux, the adapter rejects symlinks, hardlinks, special files, broad roots, live-project source mounts and overlapping source/suite paths. It copies bounded source and suite trees to disposable private views and mounts only those views read-only, explicit runtime paths and a bounded writable tmpfs. Bubblewrap uses separate network and PID namespaces, no inherited environment, no shell and no host root bind. prlimit bounds CPU, address space, per-file size, open descriptors and process count. The trusted launcher checks scratch file count; stdout/stderr, wall time and concurrent attempts are bounded. Cancellation and timeout kill the process group, wait for close, then remove the private copies. Sandbox or runner failure is BLOCKED.

**Limits and evidence gaps:** File-count checks sample at 10 ms and again at child exit; a short create/delete burst can evade the count. Hosts requiring a hard inode quota must provision a quota-enforced runner and report BLOCKED until then. The host must attest the protected source snapshot and suite digest; P4 compares identities and isolates copied bytes but does not define an independent cross-project digest algorithm. Runtime libraries are explicit host-approved mounts. Linux needs working bubblewrap namespaces and prlimit; other platforms currently block. Private scratch is deleted after the run, so durable artifacts need a separately approved collector. These gaps do not qualify a release.

Tests must cover command injection attempts, traversal/symlink/hardlink escapes, test mutation, filesystem and network boundaries, timeouts, stale source, cleanup, and false pass rejection.

## Historical audited boundary

The pre-P4 verifier cleared the child environment and used a network namespace, but read all of the host via a read-only bind and executed from the live project. That implementation was not confidentiality isolation. P4 replaces it with the bounded adapter above; platform and inode-quota gaps remain.

Trusted invocation reason `milestone | final | post_repair | manual` is separate from original T1–T4 triggers, and must carry task/milestone, source/suite/run ID, approved gate subset/regression coverage. A regular edit does not run acceptance tests. Milestone verifies its subset, repaired snapshot is reverified, and final covers the required complete manifest. Missing verifier cannot be treated as success.

Subprocess nonzero return with attributable structured Vitest assertion details is FAIL; nonzero due to crash, timeout or missing/corrupt report is BLOCKED. Both subprocess and injected verifier converge on one validator. [Audit A04–A06](../tasks/p1/codebase-gap-audit.md).
