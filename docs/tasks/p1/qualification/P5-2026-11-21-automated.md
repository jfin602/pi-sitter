## Scope and gaps

The adapter requires an embedding host to provide an operation-specific dispatcher, a current connected-server identity attestation, argument/resource authorization and result screening. Without all of these, the standalone extension exposes only `pi_sitter_inspect`. Pi 1.5.2 `getAllTools()` exposes name/schema/source path but not the built-in MCP connection's config source or endpoint; there is no extension API to invoke an existing worker MCP tool outside a worker tool's `executeTool` context. `getActiveTools()` is only model visibility. The test proves controlled read parity and host refusal, but does not prove a live model selecting and calling the proxy or qualify arbitrary third-party servers, secret stores, network endpoints and transports. Those require separate host adapter review and manual Pi/MCP qualification. No Phase 1 GREEN, formal acceptance outcome, tag or publication is claimed.

**P6 handoff:** Preserve operation and receipt identity while bounding capture-time work, provider output and saved byte-copy provenance. Denied/error MCP results and stale reports cannot become supporting diagnosis evidence. The host adapter and real connected-server attestation remain mandatory for each qualified MCP service; snapshot inspection remains the fallback.
